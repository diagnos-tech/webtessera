# ADR-0036: `state_test.ts` inlines the bundle-entry encoding instead of depending on the root package

- **Status:** proposed
- **Date:** 2026-08-19
- **Author:** layout agent
- **Upstream reference:** `api/state_test.go`, `entry.go`

## Context

`api/state_test.go` builds its input by calling into Tessera's **root** package:

```go
_, _ = bundleRaw.Write(tessera.NewEntry(want[i]).MarshalBundleData(uint64(i)))
```

That is an upward dependency: `package api_test` imports `github.com/transparency-dev/tessera`, which
imports `api`. Go tolerates it because the external test package `api_test` is compiled separately.

`entry.go`'s `NewEntry` installs this as the default `marshalForBundle`:

```go
e.marshalForBundle = func(_ uint64) []byte {
	r := make([]byte, 0, 2+len(e.internal.Data))
	r = binary.BigEndian.AppendUint16(r, uint16(len(e.internal.Data)))
	r = append(r, e.internal.Data...)
	return r
}
```

— a big-endian `uint16` length prefix followed by the data, per https://c2sp.org/tlog-tiles. The
`index` argument is ignored on this path. `NewEntry` also computes an identity hash and an RFC6962
leaf hash, neither of which this test looks at.

The root package is a different work package and did not exist when `api/state.ts` was ported.
TypeScript's module graph has no equivalent of Go's external test package, so importing it would make
`src/api` genuinely depend on the root, in both the test and the type graph.

## Decision

`src/api/state_test.ts` declares a local four-line `marshalBundleData(data)` helper that performs the
same two-step encoding, built on `appendUint16BE` and `concatBytes` from `gostd/bytes`. A
`// Port note:` on the helper names `entry.go` as the original and points here.

The helper takes no index parameter, because the code path it stands in for ignores it.

When the root package lands, this stays as it is. Re-pointing the test at `newEntry(...).marshalBundleData(i)`
would reintroduce the upward dependency for no gain in coverage.

## Consequences

- The test no longer proves that `EntryBundle.unmarshalText` round-trips against *the encoder the
  library actually uses*. It proves it round-trips against the tlog-tiles spec encoding, restated.
  If the root package's `marshalBundleData` ever drifts from the spec, this test will not notice.
- That gap is real and needs closing elsewhere. Two things close it, neither of them mine to write:
  the root package's own `entry_test.ts`, and the `api_entry_bundle` golden fixture in
  `fixtures/gen/main.go`, which is generated by running upstream Go and therefore pins the true
  encoder's output. **The fixture is the one that matters** — when `fixtures/data/api_entry_bundle.json`
  exists, `state_test.ts` should gain a case asserting against it.
- The duplication is four lines of a two-field format that is fixed by a published spec. If it ever
  changes, every fixture in the repository changes with it, which is a much louder signal than a
  failing unit test.

## Alternatives considered

- **Import the root package's `newEntry` once it exists.** Faithful to upstream's test, and the
  obvious first instinct. Rejected: Go's external test packages make that dependency free, and
  TypeScript's do not — `src/api` would import from `src/`, which inverts the layering that the rest
  of the port maintains. It would also have blocked this work package on another.
- **Hard-code the expected bundle bytes as a literal.** Rejected: with entry lengths of
  `0, 100, 200, …, 25400` bytes the literal would be enormous, and hand-writing expected bytes is
  exactly what golden fixtures exist to avoid.
- **Skip `TestLeafBundle_MarshalTileRoundtrip` until the root package lands.** Rejected: `AGENTS.md`
  §4 forbids skipped tests, and the case is the only one covering multi-entry decoding with varying
  lengths.

## Review

- **Reviewer:** Layout Reviewer (2026-08-19)
- **Verdict:** approved
- **Notes:** The `marshalBundleData` helper in state_test.ts inlines the same two-step encoding
  (`appendUint16BE` length prefix + data) that entry.go's default `marshalForBundle` performs, carries
  a `// Port note:` naming entry.go, and drops the ignored index argument — all as described. Avoiding
  the upward `src/api → src/` dependency is correct; TypeScript has no external-test-package escape
  hatch. The coverage gap the ADR flags honestly (round-tripping against the spec restated, not against
  the real encoder) is genuinely closed by `state_fixtures_test.ts`, which asserts `EntryBundle.
  unmarshalText` against the Go-generated `api_entry_bundle` fixture — I confirmed that fixture test
  runs and passes. The ADR pre-dates that fixture and predicted exactly this closure.
